# 开发规划：LSTM / GRU 唐诗字符级语言模型

## 1. 目标与范围

使用同一份唐诗语料、同一预处理和数据划分，训练单向 LSTM 与单向 GRU 字符级自回归语言模型。以独立测试集字符困惑度为主指标，辅以生成样例和可量化的生成分析。最终提交可复现实验代码、配置和日志，以及按 Abstract / Introduction / Related Work / Method / Experiment / Result / Conclusion 组织的 XeLaTeX 报告。

当前已完成规划、基建、数据管线、C 阶段模型训练、D 阶段评估生成以及三个随机种子的主实验。下一阶段整理图表并撰写论文。报告模板中的数字、表格和结论必须由实际运行产生，不预填结果。

## 2. 已核对的参考材料

- 数据源：[nndl/llm-beginner/poetryFromTang.txt](https://github.com/nndl/llm-beginner/blob/master/poetryFromTang.txt)。原文件以空行区分诗篇，诗内含换行和中文标点；源文件也含可见的疑似噪声，如 `屈rH猛`。预处理须显式记录规则，不得默默修订诗文。
- 模型接口采用 PyTorch 的 `nn.LSTM` 和 `nn.GRU`。依赖安装须与平台、CPU/CUDA 匹配，参照 [PyTorch 官方安装页](https://pytorch.org/get-started/locally/)。

## 3. 数据协议

1. 下载原文到 `data/raw/`，保留字节内容，记录 URL、获取日期、SHA-256 和文件大小。缓存的原始文件不被处理脚本覆盖。
2. 以空行切成诗篇，统一换行符为 `\n`、去掉每篇首尾空白，默认保留诗内换行、标点、异体字和疑似噪声。清洗方案若改变，必须拥有独立配置与结果；不能只对某个模型清洗。
3. 先按完整诗篇规范化文本去重，再用固定种子 42 按篇划分 train/validation/test = 80/10/10。写出划分清单、篇数、字符数、重复篇数及 SHA-256。检查三个集合诗篇哈希无交集。短语重复与同诗不同版本的潜在泄漏须在局限性中说明。
4. 词表只从训练集字符建立，固定特殊符号 `<pad>`、`<bos>`、`<eos>`、`<unk>` 的 ID；验证和测试未见字符映射到 `<unk>`，报告 OOV 率。固定词表文件与排序规则，以保证不同模型使用同一输入空间。
5. 每篇编码为 `<bos> + 字符序列 + <eos>`，不跨诗篇拼接。长度超限时以不重叠或带重叠窗口处理，必须保证每个目标 token 在评估中恰好计数一次。批处理填充位从损失和 token 数中排除。

## 4. 模型和训练

共同结构：`Embedding(V, d) -> 单向 RNN -> Linear(h, V)`，RNN 类型分别为 LSTM / GRU。默认建议 `d=128, h=256, layers=2, dropout=0.2`，根据 CPU/GPU 实测资源调整；若调整，同一比较表中保持相同设置，并额外列出参数量。训练目标为 teacher forcing 下的下一字符交叉熵。优化器 AdamW，梯度裁剪，早停依据验证集负对数似然；保存最佳验证 checkpoint 和全部运行配置。

随机性：固定 Python、NumPy（若使用）和 PyTorch 种子；记录设备、Python/PyTorch 版本和训练时长。最少 3 个随机种子用于主要比较，报告均值与标准差。如果计算资源不足，明确标为单次运行并避免显著性结论。训练/验证/测试划分和词表只生成一次，所有对照共享。

## 5. 指标与公平比较

主要指标是**字符级**困惑度：

\[
\mathrm{PPL}=\exp\left(\frac{\sum_{i=1}^{N}-\log p_\theta(y_i\mid y_{<i})}{N}\right).
\]

这里 `N` 是测试集中被预测的字符与 `<eos>` 的总数，**不计** `<bos>` 和 `<pad>`。先跨批次累加负对数似然与 token 数，再取指数；不能对批次 PPL 取平均。测试集只在模型选择结束后评估。还需报告交叉熵（nats/字符）、OOV 率、参数量、训练时间和峰值显存（若可用）。

基线：字符 unigram 或 bigram 加平滑的统计模型，用相同划分和词表评估；该基线主要提供任务难度参照。模型大小、上下文窗口和训练预算应一致；当 LSTM/GRU 参数量不同，明确注明并可补一个近似参数量匹配对照。

## 6. 文本生成与特色分析

核心生成实验：相同起始提示、随机种子和最大长度，比较贪心、温度采样与 top-k / top-p 采样。停止符为 `<eos>`，生成阶段禁止采样 `<pad>`、`<bos>`、`<unk>`。展示多个提示的原样输出，不只挑选最好的一首。

特色分析设计为**格律启发的可选约束解码**：在五言或七言模式下，用位置规则约束每句汉字数与逗号/句号位置；同一模型分别运行无约束和有约束解码。它只作用于生成，**不改变**困惑度评估。报告有效句长比例、重复字符/重复 n-gram 比例、与训练诗篇的完全匹配率和若干固定种子样例。格律启发只保证表层长度和标点，不能声称满足平仄、押韵或诗歌质量；必要时补人工盲评并公开评分标准。

可选消融：保留诗内换行与将其规整为特殊行界符；比较对 PPL 与生成行结构的影响。消融必须重新固定数据处理配置，结果不与主实验混表解释。

## 8. 预期运行产物

每次运行写入 `runs/<run-id>/`：`config.json`、`environment.json`、逐 epoch 指标、最佳 checkpoint、测试结果、生成样本及配置。`data/processed/` 保存划分索引、词表及数据审计记录。报告表格从这些产物整理，报告中标出 run ID 和原始语料 SHA-256。

## 9. 风险与处理

- 数据集较小，LSTM/GRU 容易过拟合：固定验证集、早停、训练/验证曲线和多种子结果；不以挑选单个生成样例代替量化比较。
- 诗篇长度与体裁不一致：报告长度分布；生成约束实验只比较适用样例，明确其覆盖范围。
- 源文件有噪声、缺作者与标题：只就该文件作语言建模结论，不做作者风格或历史真实性推断。
- 小语料字符词表引起 `<unk>`：记录验证/测试 OOV，必要时比较词表策略并独立呈现。
- TeX 环境尚未就绪：XeLaTeX 安装后再编译论文；模型训练所需的 PyTorch 和 CUDA 已通过验证。
